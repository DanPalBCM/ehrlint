# LK001 — `post_index_features`

**Events or features timestamped after the index date.**

| | |
| --- | --- |
| default severity | `error` |
| injector | `ehrlint.inject.inject_lk001` |

## Why this matters

A model that sees the future cannot be deployed. This is the most common and most damaging leak: a feature computed over a window that extends past the prediction time will often be the model's strongest signal, and it will be entirely unavailable at inference.

## What it looks like in practice

A feature pipeline that aggregates "all labs for this patient" without a cut-off at the index date, or a feature matrix whose as-of timestamp was taken from the outcome rather than the prediction moment.

## A note on severity

The event-level branch is an **observation**, not an error. Outcomes and follow-up live after the index date, so every real dataset has post-index events; flagging their existence would make this check permanently red and teach you to ignore it. Supply `--features` to get the error branch, which can show that post-index information reached the matrix.

## The query it runs

```sql
SELECT * FROM features f JOIN index_dates i USING (subject_id)
WHERE f.prediction_time > i.index_date
```

On the clean synthetic cohort, which is clean by construction:

```bash

ehrlint synth --out leaky/ --n-subjects 120 --seed 0 --inject LK001

  --labels leaky/labels.parquet --splits leaky/splits.json --checks LK001
```

## What to do about it

Cut every feature window at the index date, and carry an explicit as-of timestamp on the matrix so the cut is checkable rather than assumed.
