# LK002 — `same_encounter`

**Outcome codes from the index encounter itself.**

| | |
| --- | --- |
| default severity | `error` |
| injector | `ehrlint.inject.inject_lk002` |

## Why this matters

Codes are often entered at the end of an encounter, after the outcome is known. A diagnosis coded during the index visit may postdate the prediction moment even though its timestamp does not, because the timestamp is the visit's, not the moment of entry. Same-encounter outcome codes are therefore suspect regardless of their recorded time.

## What it looks like in practice

A diagnosis coded at discharge from the index visit. Its timestamp is the visit date, so a naive `time <= index_date` filter keeps it -- but the code was entered once the outcome was already known.

## The query it runs

```sql
WITH idx AS (
  SELECT subject_id, encounter_id AS index_encounter FROM events e
  JOIN index_dates i USING (subject_id) WHERE e.time = i.index_date
)
SELECT * FROM events e JOIN idx USING (subject_id)
WHERE e.code IN outcome_codes AND e.encounter_id = idx.index_encounter
```

## What to do about it

Exclude the index encounter's codes from the feature window, or move the index date to the encounter's start and use only codes that predate it.
