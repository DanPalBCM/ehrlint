# LK003 — `outcome_proxy`

**User-listed proxy codes occurring pre-index.**

| | |
| --- | --- |
| default severity | `warning` |
| injector | `ehrlint.inject.inject_lk003` |

## Why this matters

A treatment given only to cases is a label in disguise. If insulin infusion appears pre-index in a DKA prediction task, the model learns the treatment, not the risk, and will fail on patients who have not yet been treated. Proxies are task-specific and cannot be inferred, so they must be declared in the task spec.

## What it looks like in practice

An insulin drip order before the index date in a DKA task, or a dialysis code before an end-stage-renal-disease outcome. The treatment implies the outcome, so a model learns the treatment.

## A note on severity

A warning, not an error: whether a code is a proxy is a clinical judgement about your cohort, and ehrlint only knows the list you gave it.

## The query it runs

```sql
SELECT * FROM events e JOIN index_dates i USING (subject_id)
WHERE e.code IN proxy_codes AND e.time <= i.index_date
```

## What to do about it

Decide whether the proxy belongs in the task at all. If a patient already receiving the treatment is not the population you mean to predict for, exclude them; if they are, the proxy has to come out of the features.
