# LK004 — `immortal_time`

**Subjects who could not have had the outcome during follow-up.**

| | |
| --- | --- |
| default severity | `error` |
| injector | `ehrlint.inject.inject_lk004` |

## Why this matters

A subject labelled negative who left the data after one month is not a two-year negative -- they are censored. Counting them as negatives means the negative class is partly made of people who had no opportunity to have the outcome, which inflates every metric and is the classic immortal-time error.

## What it looks like in practice

A negative label on a patient whose record stops three months after the index date in a two-year task. They were never observed long enough to have the outcome, so calling them a negative counts censoring as evidence.

## The query it runs

```sql
WITH followup AS (
  SELECT subject_id, MAX(time) AS last_event_time FROM events
  WHERE time IS NOT NULL GROUP BY subject_id
)
SELECT * FROM index_dates i LEFT JOIN followup f USING (subject_id)
WHERE DATEDIFF('day', i.index_date, f.last_event_time) < 730.5
  AND subject_id NOT IN (outcome_subjects UNION competing_event_subjects)
```

## What to do about it

Require the full horizon for negatives and drop the rest, or switch to a time-to-event formulation that handles censoring explicitly.
