# LK006 — `temporal_split`

**Test index dates that precede the training period's end.**

| | |
| --- | --- |
| default severity | `warning` |
| injector | `ehrlint.inject.inject_lk006` |

## Why this matters

A split described as temporal but not ordered in time reports an optimistic number: the model is evaluated on a period it was partly trained on, so it benefits from knowing the era's coding practices, formulary, and case mix.

## What it looks like in practice

A random split described in the paper as temporal, or a temporal split taken on admission date while the index date is something else.

## A note on severity

`error` when the task spec declares `splits.temporal: true`, `warning` otherwise. A declared property that does not hold is a broken claim; an undeclared one is a design question.

## The query it runs

```sql
WITH train_max AS (
  SELECT MAX(index_date) AS t FROM index_dates
  WHERE subject_id IN train_split
)
SELECT * FROM index_dates WHERE subject_id IN test_split
  AND index_date < (SELECT t FROM train_max)
```

## What to do about it

Split on the same timestamp the task indexes on, and check the boundary rather than trusting the sort.
