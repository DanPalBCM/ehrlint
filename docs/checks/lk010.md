# LK010 — `horizon_violation`

**Outcome occurrences beyond the declared horizon.**

| | |
| --- | --- |
| default severity | `error` |
| injector | `ehrlint.inject.inject_lk010` |

## Why this matters

A two-year task whose outcome window actually reaches five years is a five-year task reported as two. Every metric is then describing a different question from the one the paper states, and the model will underperform when deployed against the stated horizon.

## What it looks like in practice

A positive label from an outcome three years after the index date in a two-year task -- usually a label query with no upper bound on time.

## The query it runs

```sql
SELECT * FROM events e JOIN index_dates i USING (subject_id)
WHERE e.code IN outcome_codes
  AND DATEDIFF('day', i.index_date, e.time) > 730.5
  AND e.subject_id NOT IN (subjects with an in-window occurrence)
```

## What to do about it

Bound the outcome query by the horizon, and recount the positives afterwards. The prevalence will drop; that drop was always the truth.
